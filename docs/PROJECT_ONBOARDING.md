# Project Onboarding

## Сценарии

Internship — персональный учебный маршрут, отображаемый для внутреннего сценария `COMPANY`. Project Onboarding — подключение к назначенному проекту, внутренний сценарий `PROJECT`. Тип профиля `INTERN`/`EMPLOYEE`, стартовый сценарий и роль безопасности независимы.

Новый аккаунт получает роль `EMPLOYEE`. Выбор сценария при регистрации не открывает проекты и не даёт административных прав. Администратор назначает сотруднику проект и проектную роль: Engineering, QA, DevOps/SRE или General.

## Доступы и данные

В списке рабочих пространств видны общие материалы и только активные назначения сотрудника, включая демонстрационные проекты. Проверка участия выполняется на сервере для документов, маршрута, задач и истории чата.

Личный маршрут содержит этапы CONTEXT, ENVIRONMENT и DELIVERY. Статусы: TODO, IN_PROGRESS, BLOCKED и DONE. Для BLOCKED требуется описание препятствия. Прогресс вычисляется из сохранённых статусов. Повторное назначение не сбрасывает выполненные шаги. Отзыв участия закрывает доступ, сохраняя прогресс и историю; восстановление возвращает доступ к ним.

История разделена по сотруднику и контексту. Использование conversation_id другого проекта отклоняется. Административная роль сама по себе не открывает проектные материалы без участия в проекте.

## API

- `GET /api/v1/projects` — назначенные проекты.
- `GET /api/v1/projects/{project_id}/onboarding` — личный маршрут.
- `PATCH /api/v1/projects/{project_id}/onboarding/tasks/{task_id}` — статус и blocker_note.
- `GET /api/v1/projects/{project_id}/documents` — доступные документы проекта.
- `PUT /api/v1/admin/employees/{employee_id}/projects/{project_id}` — назначение, отзыв или восстановление участия.
- `PATCH /api/v1/admin/employees/{employee_id}/profile` — тип профиля и сценарий.

Чат принимает выбранный `project_id` в `/api/v1/chat` и `/api/v1/chat/stream`. Проектный поиск не использует общий корпоративный индекс как запасной источник. Персональные статусы обрабатываются локально, отдельно от генерации.

## Локальная подготовка

Для новой или ещё не подготовленной базы предусмотрены добавочные настройки:

```powershell
.\venv\Scripts\python.exe -m tools.setup_project_onboarding
.\venv\Scripts\python.exe -m tools.setup_project_access
```

Они не предназначены для сброса данных. Команды запуска приложения находятся в [README](../README.md). Проверки описаны в [ANSWER_QUALITY](ANSWER_QUALITY.md).
